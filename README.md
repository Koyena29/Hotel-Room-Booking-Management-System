# Hotel Room Booking Management System

## Project Overview
The **Hotel Room Booking Management System** is a MySQL database project designed to manage hotel rooms, guests, bookings, payments, and booking-related reports. The sample database is named `hotel_db` and is based on the **Grand Horizon Hotel** dataset.

The project demonstrates practical database concepts such as table creation, relationships, constraints, indexes, triggers, views, transactions, data import/export, and reporting queries.

## Objectives
- Maintain hotel room types, rooms, and guest records.
- Record guest bookings, check-in/check-out dates, guest counts, and booking statuses.
- Calculate booking totals automatically based on room price and stay duration.
- Prevent overlapping active bookings for the same room.
- Track payments and outstanding balances.
- Generate operational and revenue reports.
- Maintain an audit trail of booking and payment activity.

## Technologies Used
- **Database:** MySQL 8.0
- **Language:** SQL
- **Dataset:** Sample register of 30 guests, 30 rooms, and 5 room types

## Database Structure

The database contains the following tables:

| Table | Purpose |
|---|---|
| `room_types` | Stores room categories and nightly prices |
| `rooms` | Stores room numbers, floors, room types, and room status |
| `guests` | Stores guest IDs, names, contact details, and guest codes |
| `bookings` | Stores reservation dates, guest counts, totals, and booking statuses |
| `payments` | Records payment amounts, methods, and timestamps |
| `audit_log` | Stores audit entries generated by triggers |
| `stg_register` | Staging table used when importing guest-register CSV data |

### Relationships
- A room type can be assigned to many rooms.
- A guest can have multiple bookings.
- A room can have multiple bookings over time.
- A booking can have multiple payment records.

## Main Features

### 1. Database and Table Creation
Creates the `hotel_db` database and all required tables with primary keys, foreign keys, unique constraints, checks, and defaults.

### 2. Sample Data
Loads room types, 30 rooms, and 30 sample guests. It also includes sample bookings and advance-payment records.

> Payment details in the SQL are sample data; the source guest CSV does not contain payment, email, or phone information.

### 3. Automatic Booking Total Calculation
A trigger calculates the booking amount using the room's nightly rate multiplied by the number of nights.

### 4. Booking Conflict Prevention
A trigger prevents active bookings from overlapping for the same room and raises an error if a conflict is detected.

### 5. Room Status Updates
Triggers update room status after bookings are inserted and release rooms when bookings are cancelled or completed.

### 6. Payment Validation
A trigger prevents payments from exceeding the booking total and records payment activity in the audit log.

### 7. Audit Logging
The `audit_log` table records booking and payment events, including insertions and room-release actions.

### 8. Views
The SQL script creates:
- `v_available_rooms` — rooms available for the current date, excluding maintenance rooms and rooms with active bookings.
- `v_booking_summary` — booking details combined with guest, room, room type, and paid amount.
- `v_unpaid_bookings` — active bookings with outstanding balances.

### 9. Transactions
Demonstrates:
- `START TRANSACTION`
- `COMMIT`
- `ROLLBACK`
- `SAVEPOINT`
- Rollback handling for a failed multi-room booking procedure

### 10. Reports and Analysis
The project includes queries for:
- Available rooms
- Booking details
- Bookings by date
- Monthly bookings and room nights
- Revenue by room type
- Repeat guests
- Booking counts by status
- Top bookings by amount
- Most valuable guest per room type
- Unpaid bookings and outstanding balances

### 11. Indexing and Performance
Indexes are created for room status, booking date/room searches, guest booking lookups, booking status, and payment booking IDs. An additional example compares query plans before and after indexing guest names using `EXPLAIN`.

### 12. CSV Import and Export
The script demonstrates exporting booking summaries to CSV and importing guest-register data through the staging table `stg_register`.

## Installation and Setup

1. Install and start MySQL Server 8.0.
2. Open MySQL Workbench or the MySQL command-line client.
3. Open/import `hotel_booking.sql`.
4. Execute the SQL script.

The script creates the database `hotel_db`. **Note:** The script begins with `DROP DATABASE IF EXISTS hotel_db`, so running it will delete an existing database with that name before recreating it. Back up any important data first.

### Command-line execution
From your operating-system terminal:

```bash
mysql -u root -p < hotel_booking.sql
```

Enter your MySQL password when prompted.

### Verify the database
After execution:

```sql
USE hotel_db;
SHOW TABLES;
SELECT * FROM v_available_rooms;
SELECT * FROM v_booking_summary;
SELECT * FROM v_unpaid_bookings;
```

## CSV Import and Export Notes
MySQL file import/export may require a permitted directory configured by `secure_file_priv`.

Check the directory:

```sql
SHOW VARIABLES LIKE 'secure_file_priv';
```

Place the CSV file in that permitted folder and update the file paths in the SQL script if your environment uses a different location. The script's sample paths use `/var/lib/mysql-files/`.

## Backup and Restore

Run these commands in the operating-system terminal, not inside the MySQL SQL editor.

### Backup
```bash
mysqldump -u root -p --routines --triggers hotel_db > hotel_backup.sql
```

### Restore
```bash
mysql -u root -p -e "DROP DATABASE hotel_db; CREATE DATABASE hotel_db;"
mysql -u root -p hotel_db < hotel_backup.sql
```
